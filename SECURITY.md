# Security policy

## Reporting a vulnerability

Use the repository's **Security → Advisories → Report a vulnerability** action to submit a private report when available. Include the affected revision, Windows version, minimal reproduction, impact and a proposed fix if known. Remove credentials, personal paths and media from attachments.

Do not publish exploit details or secrets in a public issue. If private reporting is unavailable, open an issue requesting a private contact method without including vulnerability details. Maintainers must enable private vulnerability reporting before public launch; adding this file does not enable that setting.

See [GitHub's private reporting guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

## Supported versions

Security fixes target the latest `main` revision. There is no supported public binary release or promised response time. Older packages should not be treated as maintained distributions.
